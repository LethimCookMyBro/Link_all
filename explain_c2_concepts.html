1. Disconnect (ตัดสายชั่วคราว)
สั่งผ่าน Dashboard UI (กดปุ่ม D)

เปรียบเหมือน รปภ. เดินไปสะกิดบอกเครื่องลูกว่า "ตัดการเชื่อมต่อ Socket ตอนนี้ออกไปก่อน"

  • ผลลัพธ์: สายหลุดทันที (Session Closed)
  • ใบบัตรผ่าน (Certificate): ยังคงใช้งานได้ปกติ
  • ข้อควรรู้: Agent สามารถหมุนตั้งเวลา Reconnect กลับมาใหม่ได้เมื่อไหร่ก็ได้
🚫
2. Revoke (แบนถาวร)
สั่งผ่าน Terminal (CLI Command)

เปรียบเหมือนการเดินไปที่ สมุดทะเบียนกลาง (Database) แล้วขีดฆ่าทำลายบัตรอนุญาตทิ้ง

  • ผลลัพธ์: บันทึกลง SQLite DB ว่า Agent นี้ถูกเพิกถอนแล้ว
  • ใบบัตรผ่าน (Certificate): ถูกทำลายทิ้งทันที
  • ข้อควรรู้: ต่อให้ Agent พยายามต่อสายกลับมา จะถูกระบบม้าเร็ว mTLS ปฏิเสธตั้งแต่ประตูหน้า

🛡️ ทำไม Red Team ถึงไม่แนะนำให้สร้าง "ท่อเชื่อมพิเศษ" (Local IPC)?

การพยายามทำให้คำสั่ง Terminal สั่ง Disconnect ได้โดยตรง ต้องแอบเจาะช่องทางสื่อสารพิเศษ (Local IPC) เชื่อมเข้า Dashboard ซึ่งเพิ่มความเสี่ยงโดยไม่จำเป็น

📌 สรุปมุมมอง Security: หากมีแฮกเกอร์สามารถเข้าถึงเครื่องแม่ข่าย C2 ของเราได้ (Local Privilege Escalation) แฮกเกอร์อาจแอบส่งสัญญาณผ่าน "ช่องท่อเชื่อมพิเศษ" นี้เพื่อมาป่วนหรือตัดสาย C2 Agent ของเราทั้งหมดได้!
สรุปทางออกที่ปลอดภัยและลงตัวที่สุด

การเลือกแนวทางนี้ช่วยให้ระบบสะอาด ปลอดภัย และตรงตามหลักเกณฑ์ของ Red Team Architecture

1. ปิดการตั้งค่า CLI Disconnect ตัดคำสั่ง Disconnect ออกจาก Terminal เพื่อไม่ต้องสร้างท่อสื่อสารที่เสี่ยงโดนแฮก
2. ใช้ Dashboard ตัดสายชั่วคราว เมื่อต้องการ Disconnect สั่งจากหน้าจอ Dashboard (กดปุ่ม D) ซึ่งอยู่ใน Memory เดียวกัน
3. ใช้ Terminal สั่งแบนถาวร เมื่อต้องการ Revoke สั่งผ่าน Terminal ได้ปกติเพราะไปอัปเดตไฟล์ฐานข้อมูล SQLite ตรงๆ
